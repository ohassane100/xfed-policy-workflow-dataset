## 1. Project context

The XFed project involves translating legal or business contracts into structured, machine-readable policies, reviewing those policies using LLMs, and eventually generating and validating executable workflows.

The agreed pipeline is:

1. **Contract preprocessing:** Extract PDF text and split it into contract clauses.
2. **Policy generation:** A central LLM converts contract clauses into structured `policy.json`.
3. **Policy review:** Independent company-side LLMs verify policies against their source clauses using labels such as ENTAILED, CONTRADICTED, UNSUPPORTED, and AMBIGUOUS.
4. **Human approval:** Policies are approved or revised before further processing.
5. **Workflow generation:** Approved policies are converted into executable YAML workflows.
6. **Workflow validation and execution:** Later stages verify that workflows satisfy the agreed policies.

The immediate goal is to deploy LLMs on UiS's Gorina5 infrastructure to support the contract-to-policy pipeline, particularly policy generation and independent review.

## 7. Python integration with Ollama

Once an LLM is available, Python can call the REST API directly.

Example:

```python
import requests

url = "http://localhost:11434/api/generate"

payload = {
    "model": "qwen3:4b",
    "prompt": "Extract the data-sharing obligations from this contract clause.",
    "stream": False,
}

response = requests.post(url, json=payload, timeout=300)
response.raise_for_status()

print(response.json()["response"])
```

Install the Python dependency inside the XFed environment:

```bash
conda activate xfed
python -m pip install requests
```

For structured policy generation, use Ollama's JSON-schema structured-output capabilities together with Pydantic.

This is particularly relevant to the existing XFed contract-to-policy architecture.
